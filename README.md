# Game News Nexus

ゲームのお知らせを集めて読む、Windows と macOS (Apple Silicon) 向けの常駐型デスクトップアプリ。Rust と
[gpui](https://gpui.rs) ([gpui-kit](https://gpui-kit.com)) で作っています。

DMM GAMES の各タイトルのお知らせを集めていた `dmm-games-info` (Python) と、その結果を
読む `tauri-dmm-game-info` (Tauri + React) を 1 つにまとめたものです。ゲームごとの取得の
定義は別のリポジトリ [game-news-nexus-config](https://github.com/owayo/game-news-nexus-config)
(カタログ) で管理していて、利用者は読みたいゲームを on/off するだけで使えます。
カタログにないゲームも、手元で取得の定義を書けば追加できます。

## できること

- **お知らせを集めて読む**: 左に記事の一覧 (新しい順)、右に本文。本文の HTML は
  画像ごと表示し、画像は手元にキャッシュするので配信が消えても読めます。取得で見かけた画像は
  1 日に 1 回配信元で確かめ直し (ETag・Last-Modified)、差し替わっていれば入れ直します。キャッシュの画像は
  書いたときの長さと SHA-256 で照らしてから表示し、壊れていれば取り直します。
- **予定を読み取る**: お知らせの題名と本文から、メンテナンスの予定と結果 (終了・延長・中止・延期) と、
  イベント・ガチャ・キャンペーンなどの期間を読み取ります (「予定の読み取り」)。一覧の行と記事の見出しに
  「メンテ中 (17:00 まで予定)」「メンテ 11/12(木) 14:00–17:00」「終了予定を過ぎています」「メンテ終了」などの
  バッジを出し、記事の詳細には読み取った予定と、根拠にした記事の記述を出します。
- **今日・明日の予定を上に**: メンテナンスの時間帯が今日・明日に重なる記事 (予定の時間内・終了未定・
  終了予定を過ぎたばかりのものを含む) と、イベント・ガチャ・キャンペーンが今日・明日に始まる・終わる
  記事を、一覧の上にまとめます (今日の分は太字)。補填の受け取りや販売の期限は数えません。新しい順で
  5000 件より古い記事に書かれた予定も拾います。予定の開始・終了の時刻、日付の変わり目、スリープからの
  復帰で並べ直します。
- **メンテナンスの印**: サイドバーのゲーム名の横に、メンテナンスの予定の時間内か、今日メンテナンスが
  あることを示す印を出します。
- **追記に追いつく**: 詳細ページから本文を取るソースは、投稿から 48 時間を過ぎた記事でも、メンテナンスの
  予定が近いもの (開始の 7 日前から終わりの 12 時間後まで) は本文を取り直し、当日に足された完了・延長の
  追記を拾います (一覧から外れた記事も、保存済みの URL で取り直します)。
- **検索**: タイトルと本文を全文検索し、一覧と本文で一致箇所を目立たせます。
  全角・半角、大文字・小文字、半角カナの違いは区別しません。
- **既読管理**: 開いた記事は既読になり、ソースごとの未読数をサイドバーに出します。
- **新作・近日リリース**: DMM GAMES / FANZA GAMES の新作と配信予定をカードで並べます。
- **常駐と定期取得**: ウィンドウを閉じてもタスクトレイ (macOS はメニューバー) に残り、決めた間隔で
  取得を続けます。新着は OS の通知で知らせ、通知を押すとその記事を開きます。サインイン (macOS は
  ログイン) したときに自動で起動することもできます。トレイの「終了」・`Ctrl+Q`・`--quit` で終わるときは、
  取得中の通信を取り消し、データベースへの書き込みが済むのを待ってから終わります (長くても数秒)。
  取り消した取得は、次の取得 (起動したときの取得か、間隔どおりの取得) で取り直します。
- **ゲームを選ぶ**: ソース画面でカタログのゲームを on/off します。off にしたゲームは取得も
  表示もしません。カタログは起動時と 1 日 1 回取り込み直し、追加や修正が自動で届きます。
- **手元で書く・直す**: カタログにないゲームは、取得方式 (RSS / Atom、JSON API、HTML の一覧、
  HTML に埋め込まれた JSON) を選んで手元に定義を作れます。カタログの定義を「自分用にコピー」
  して直すこともできます。「テスト取得」で、段ごとに何件取れたかを確かめられます。
- **ゲームのアイコン**: 画像を選ぶと正方形に切り抜く画面が開き、切り抜いた画像を一覧と本文に
  角丸で出します。

## カタログ

ゲームごとの取得の定義は [game-news-nexus-config](https://github.com/owayo/game-news-nexus-config)
に 1 ゲーム 1 ファイルの YAML で置いています。有志の PR で増やしていく前提です。

- アプリはカタログの写しを同梱していて、初めて起動したときはそれを使います。起動時と 1 日 1 回、
  カタログの `main` を取り込みます (変わっていなければ取り直しません)。
- 初めて起動したときは、DMM GAMES と HoYoverse (原神・崩壊：スターレイル・ゼンレスゾーンゼロ) の
  グループのゲームが on になります。ゲームメディア (4Gamer.net・GAME Watch・AUTOMATON) と Steam の
  ニュースは、ソース画面で on にできます。
- あとからカタログに加わったゲームも、既定で on のグループのものは初めて取り込んだときに on に
  なります。off にしたゲームは、カタログが更新されても off のままです。
- 取り込みはファイルごとに判断します。読めないファイルや、このアプリより新しい版を求める
  ファイル (`min_app_version`) は、そのゲームの前の版を使い続けます。前の版がなければ、
  ソース画面に「アプリ X 以降」と出します。
- カタログの場所は設定画面の「カタログ」で変えられます。取得の定義を書いて試すときは、
  リポジトリを clone したフォルダを指定すると、手元の定義がそのまま読み込まれます。

元の Python 版でブラウザ (Playwright) を使っていたソースのうち、エデンズリッター・
魔王カリンちゃん・マブラヴ・エンジェリックリンクは通常の HTTP で取れることを確かめて
移しています。ログインした上で iframe の中を読む必要がある「ステラP」は移していません。

## インストール

[Releases](https://github.com/owayo/game-news-nexus/releases/latest) から、使う環境の添付を取得します。
添付のチェックサムは `SHA256SUMS` にあります。

| 環境 | 添付 |
| --- | --- |
| Windows 10 / 11 (x64) | `game-news-nexus-<版>-windows-x64-setup.exe` |
| macOS (Apple Silicon) | `game-news-nexus-<版>-macos-arm64.dmg` |

どちらもコード署名と Apple の公証をしていないので、初めて開くときに OS の確認が出ます。

### Windows

インストーラーを実行します。管理者の権限は要らず、使っている人の `%LOCALAPPDATA%\Programs\Game News Nexus` に入り、
スタートメニューに「Game News Nexus」ができます。「Windows によって PC が保護されました」と出たら、「詳細情報」を押してから
「実行」を選びます。

- 更新するときは、新しい版のインストーラーを実行します。起動中なら、インストーラーがアプリに終了を頼み
  (`--quit`。トレイの「終了」と同じく、取得を止め、データベースへの書き込みを済ませてから終わる)、終わってから入れ替えます。画面を出して
  いるときは先に確かめ、終わらなければ閉じてから入れ替えます (`/VERYSILENT` などで黙って更新したときは、
  確かめずに終了させ、動いていたアプリをトレイで起動し直します)。
- アンインストールは「設定」→「アプリ」→「インストールされているアプリ」から行います。起動中なら同じく終了を
  頼んでから消し、この場所を指す自動起動の登録も外します。設定と記事のデータ (「データの場所」) は残すので、
  要らなければ手で消します。

### macOS

DMG を開き、`Game News Nexus` を `Applications` へドラッグしてから、「アプリケーション」から開きます。DMG の中や
ダウンロードのフォルダから直接開くと、macOS がアプリを一時的な場所から動かす (App Translocation) ので、ログイン時の
自動起動を登録できません。初めて開くと確認が出て開けないので、「システム設定」→「プライバシーとセキュリティ」の
「このまま開く」を押します。アンインストールは、設定で自動起動を切ってアプリを終了してから、
`/Applications/Game News Nexus.app` をゴミ箱へ移します (自動起動を切らずに消すと、
`~/Library/LaunchAgents/io.github.owayo.game-news-nexus.plist` が残ります)。

## 動かす

ツールのバージョンは [mise](https://mise.jdx.dev) で固定しています。

```bash
mise install
```

```bash
mise run run
```

ビルドするタスク (`build`・`run`・`test`・`lint`・`release`・`fetch-once`) は、先に予定の読み取りに使う辞書
(hasami のリリースの IPAdic、約 15 MB) を `crates/gnn-schedule/dict/` に取得します (`mise run dict`)。
`crates/gnn-schedule/dict/bundled.json` に固定した大きさと SHA-256 で照らし、2 回目からは照合だけです。
`cargo` を直接使うときは、先に `mise run dict` を実行してください。

リリース版のビルド:

```bash
mise run release
```

`target/release/game-news-nexus.exe` (macOS は `target/release/game-news-nexus`) ができます。辞書も埋め込むので、
1 つの実行ファイルで動きます。インストーラーと DMG の作り方は「開発」の「配布物を作る」にあります。

### コマンドラインのオプション

| オプション | 説明 |
| --- | --- |
| `--hidden` | ウィンドウを出さずにトレイ (macOS はメニューバー) で起動する (自動起動向け) |
| `--fetch-once` | 画面を出さずに、カタログを取り込んでから on のソースを 1 度ずつ取得し、予定も読み取って終わる。結果を標準出力に出し、失敗があれば終了コード 1 |
| `--quit` | 起動中のアプリに終了を頼み (トレイの「終了」と同じく、取得を止め、データベースへの書き込みを済ませてから終わる)、終わるまで最大 30 秒待つ。起動していなければ何もしない (データのディレクトリも作らない)。終了コードは 0 (終わった・起動していなかった)、1 (伝えられない・時間内に終わらない・別の実行ファイルで起動している) |
| `-h`, `--help` | 説明を出す |

`--hidden`・`--fetch-once`・`--quit` は一緒に使えません (終了コード 2)。

すでに起動しているときにもう一度起動すると、起動中のウィンドウを前に出して終わります (`--hidden` を
付けたときは、ウィンドウを出させずに終わります)。macOS で Dock・Finder・Launchpad から開いたときは
2 つ目は起動せず、起動中のアプリがウィンドウを出します。

`--quit` は、同じ設定とデータの場所 (`GNN_HOME`) を使い、同じ実行ファイルで起動しているアプリだけを終了させます
(別の場所の実行ファイルで起動しているときは、終了させずに 1 で終わります)。macOS では、端末から
`.app` の中の実行ファイルを直接起動します (`"/Applications/Game News Nexus.app/Contents/MacOS/game-news-nexus" --quit`)。
`open` や Dock・Finder からでは 2 つ目が起動しないので届かず、起動中のアプリを前に出すだけです。メニューの
「終了」(`⌘Q`) やメニューバーのアイコンの「終了」でも、同じ後始末をして終わります。

### キーボード

macOS では `Ctrl` の代わりに `⌘` を使います (`⌘R`・`⌘F`・`⌘1`〜`⌘3`・`⌘,`・`⌘W`・`⌘Q`)。

| キー | 操作 |
| --- | --- |
| `Ctrl+R` / `F5` | すべて取得 (ニュース画面では表示中のソース) |
| `Ctrl+F` | 検索欄へ |
| `J` / `↓`、`K` / `↑` | 次・前の記事 (一覧にフォーカスがあるとき) |
| `O` / `Enter` | 元の記事をブラウザで開く |
| `M` | 既読・未読を切り替える |
| `Shift+A` | 表示中の記事をすべて既読にする |
| `Ctrl+1` / `Ctrl+2` / `Ctrl+3` / `Ctrl+,` | ニュース / 新作・近日リリース / ソース / 設定 |
| `Ctrl+W` | ウィンドウを閉じる (閉じるボタンと同じ。設定によりトレイ・メニューバーに残り、残さない設定なら終了する) |
| `Ctrl+Q` | 終了 |

macOS では、ほかに `⌘H` (隠す)・`⌥⌘H` (ほかを隠す)・`⌘M` (しまう) が使え、メニューバーのアプリのメニュー
(設定・編集・表示・ウインドウ) からも同じ操作ができます。

### macOS で使うとき

- メニューバーのアイコンを押すとメニュー (開く・今すぐ取得・終了) が出ます (Windows のトレイと違い、
  左クリックでもメニューです)。
- Dock にアイコンが出るのはウィンドウを開いている間だけです。ウィンドウを閉じると、メニューバーの
  アイコンだけで常駐して取得を続けます。
- 「ログインしたら自動で起動する」は `~/Library/LaunchAgents/io.github.owayo.game-news-nexus.plist` を書き、
  次のログインから効きます。アプリを別の場所へ移したら入れ直してください。ダウンロードしたアプリを
  「アプリケーション」フォルダへ移さずに開いているときは登録できません。システム設定の「ログイン項目」で
  止めた場合、アプリの設定画面のスイッチには表れません。
- 通知は `Game News Nexus.app` から起動したときだけ出ます (`cargo run` などで直接起動したときは出ません)。
  初めて通知するときに、通知を許可するかを聞かれます。

## データの場所

| 内容 | 場所 |
| --- | --- |
| アプリ設定 | `%APPDATA%\game-news-nexus\config\settings.toml` |
| ゲームの on/off と手元だけの上書き (アイコン・取得間隔など) | `%APPDATA%\game-news-nexus\config\subscriptions.toml` |
| 手元の取得の定義 | `%APPDATA%\game-news-nexus\config\sources\<id>.yaml` |
| 秘密の値 | `%APPDATA%\game-news-nexus\config\secrets.toml` |
| 記事 (SQLite) | `%APPDATA%\game-news-nexus\data\nexus.db` |
| 取り込んだカタログの控え | `%APPDATA%\game-news-nexus\data\catalog.json` |
| 切り抜いたアイコン | `%APPDATA%\game-news-nexus\data\icons\` |
| ログ | `%APPDATA%\game-news-nexus\data\logs\` |
| 起動中のアプリのロックと連絡先 (二重起動の防止と `--quit`。`instance.port` には起動ごとの合言葉が入る) | `%APPDATA%\game-news-nexus\data\instance.lock`・`instance.port` |
| 画像キャッシュ | `%LOCALAPPDATA%\game-news-nexus\cache\images\` (最大 1 GB、最後に確かめてから 180 日。配信元の ETag・Last-Modified と、書いたときの長さ・SHA-256 は画像の横の `.meta`) |

macOS では、Windows の `config` と `data` に置くものを `~/Library/Application Support/game-news-nexus/` に
まとめて置き (例: `settings.toml`・`sources/<id>.yaml`・`nexus.db`・`logs/`)、画像キャッシュは
`~/Library/Caches/game-news-nexus/images/` に置きます。

環境変数 `GNN_HOME` を指定すると、すべてをそのディレクトリの下 (`config`・`data`・`cache`) に置きます。
手で編集した場合は、アプリを起動し直すと読み込みます。

## 取得の定義

取得の定義は YAML で、1 ファイルに 1 つのゲームを書きます。処理の流れは段で決まっていて、
各段で何をするかを書きます。

1. `prepare` (任意): 事前に取得し、応答から値を取り出して `{{vars.名前}}` にする
2. `lists`: 一覧を取得して記事の候補を作る。複数書くと宣言順にまとめる。上限付きのページ送りもできる
3. まとめ (アプリが行う): 重複・取得済み・古い記事を除く
4. `detail` (任意): 残った記事だけ詳細ページを取る
5. `body`: 本文を整える (置換・要素の除去・改行など)

```yaml
# ミストトレインガールズ
schema: 2
min_app_version: '26.11.6'
id: mist_train_girls
name: ミストトレインガールズ
lists:
  - kind: json
    request:
      url: 'https://fd-misttrain-prod.azurefd.net/api/info/news?gameVersion=2'
    items: '/articles'
    filter:
      - { pointer: '/visible', eq: true }
    fields:
      id: '/articleUrl'
      title: '/title'
      published: '/date'
      image: '/bannerImgUrl'
detail:
  kind: html
  request:
    url: 'https://fd-misttrain-prod.azurefd.net/api/info/news?id={{item.id}}'
body:
  image_in_body: true
```

書き方の詳細 (取得方式・取り出す項目・条件・ページ送り・差し込み・本文の整形) は、
カタログの [CONTRIBUTING.md](https://github.com/owayo/game-news-nexus-config/blob/main/CONTRIBUTING.md)
にまとめています。手元の定義もカタログと同じ書き方です。

- YAML は 1.2 の決まりで厳格に読みます。文字列は単一引用符で囲んでください
  (`#` で始まるセレクタや `{{` で始まるテンプレートを YAML の記号と取り違えないため)。
  アンカー・エイリアス・マージ・独自タグは使えません。
- アプリのソース画面では、フォームか YAML タブで書けます。YAML タブで書いたコメントは、
  フォームで値を変えない限りそのまま保存します。
- 記事は `id` → `url` → `title` の順で見分けます。訂正で新着扱いにならないよう、
  できるだけ `id` を指定してください。
- 本文の予定 (メンテナンスの日時など) を読む地域時刻は、投稿日時の `timezone` とは別に `schedule:` で
  書けます。HoYoverse の 3 タイトルは、本文の日時を日本時間で、「サーバー時間」と書かれた日時を UTC+8 で
  読みます。`schedule:` を変えても取得し直さず、保存済みの記事から読み直します。
- 画像の URL に署名・期限や取得した時刻 (キャッシュ破り) の問い合わせが付き、同じ画像でも取得のたびに
  URL が変わる配信元は、`url_identity:` に外す問い合わせを書きます。書いた画像は、記事が変わったかを
  比べるときと画像のキャッシュでは同じ画像として扱い (署名が変わっても「更新」にせず、取り直さない)、
  取りに行くときは配信元の URL をそのまま使います (署名を外すと取れない配信元があるため)。
  問い合わせを推測で外すことはしません (`?v=2` のような版は、中身が変わった印として扱います)。
  ガールズクリエイション・ドットアビス・Twinkle☆Star Knights で使っています。
  キャッシュになく、記録した URL の署名の期限も切れていた画像は、そのソースを取り直して新しい URL で
  取ります (詳細ページの画像は、その記事の詳細も取り直します。「制限」も見てください)。

  ```yaml
  url_identity:
    images:
      - origin: 'https://cdn.gc.dmmgames.com'
        path_prefix: '/secure/img/'
        ignore_query: ['s', 't']
  ```

### 秘密の値 (`secrets.toml`)

手元の定義では、ヘッダの値に `{{secret:名前}}` と書くと `secrets.toml` の値に置き換えます。
カタログの定義では使えません (第三者が書いた定義に、利用者の秘密の値を送らせないため)。

```toml
[values]
mist_cookie = "session=..."
```

### 取得先の制限

- カタログの定義は、インターネット上のアドレスだけに取得します。localhost・LAN・リンクローカルへは、
  名前解決したアドレスとリダイレクト先も確かめて接続しません。
- 手元の定義も、既定では同じ制限です。自分のサーバーなどを読むときは、編集画面の
  「手元のネットワーク (localhost・LAN) への取得を許す」を on にします。
- 本文の画像は、どの定義のものでも手元のネットワークへは取りに行きません。

## 予定の読み取り

お知らせの題名と本文から、メンテナンスの予定 (開始・終了) と結果 (完了・中止・延期・延長) と、イベント・ガチャ・
キャンペーン・販売・受け取りの期間を読み取ります。

- 日本語の文は、形態素解析器 [hasami](https://github.com/owayo/hasami) と、実行ファイルに埋め込んだ辞書 (IPAdic) で
  読みます。「予定していたメンテナンスを中止します」のような修飾節や、「終了していません」「終了したら」
  「中止する場合があります」のような否定・条件・可能性を読み分けます。
- 本文の見出し・リスト・表・取り消し線・「項目名：値」の行・追記の区画も手がかりにします。補填の受け取り期限や
  販売の終わりは、メンテナンスの時間として扱いません。
- 別の記事で報告された完了・中止・延長は、予告の記事のメンテナンスにも反映します (対象と時間帯で 1 つに決まる
  ときだけ結び付け、日付が近いだけでは結び付けません)。
- 「Android版・iOS版」のように 1 つの時間帯に複数の対象が書かれていれば、対象ごとに読み、「iOS版のみ完了」の
  ような一部の対象だけの報告もその対象に当てます。画面では、同じ状態のものを 1 つのバッジにまとめます。
- 「現在メンテナンスを実施しております」のように、開始の時刻がなく実施中とだけ書かれた告知も、いつの時点で
  実施中だったか (追記の日時、なければ投稿日時) と一緒に読み、「メンテ中」と出します (終わりが書かれていなければ
  その時点から 24 時間まで)。
- 延長は延長する前の終わりと新しい終わりを、日程変更は変更ごとの前と後を読み、「延長 11/12(木) 17:00 → 19:00」
  「日程変更 11/10(火) 14:00–17:00 → 11/12(木) 14:00–17:00」のように並べて出します。イベントなどの期間の延長・
  変更も読み、延びた期間のバッジには「(延長)」を付けます。今日・明日かは、変更の後の期間で決めます。
  始まる前に書かれた「延長します」は実施中とは扱わず、延長する前の終わりが書かれていなければ、それまでの予定の
  終わりを推定で出します。
- 決められない日時 (曜日の食い違い、終わりが始まりより前、「サーバー時間」の地域時刻が分からないなど) は推測せず、
  記事の詳細に理由を出します。年の書かれていない日付は投稿日に近い年にし、`24:59` は翌日の 0:59 と読みます。
- 予定の時間内でも、完了の報告がなければ予定のままとし、終了予定を過ぎても完了とはみなしません
  (「終了予定を過ぎています」と出します)。日付だけの予定は「メンテ中」にせず、所要時間から求めた終わりには
  「頃」を付けます。
- 読み取った結果は、記事から作り直せるデータとして保存します。読み取り方を変えた版のアプリでは、起動したときに
  保存済みの記事を読み直します。

## 旧形式との連携

- **`sources.toml` (書式 1) からの移行**: 以前の版の `sources.toml` が残っていれば、初めて起動したときに
  自動で移します。カタログと同じ ID のソースはカタログの定義を使い、on/off・アイコン・取得間隔・期間を
  `subscriptions.toml` に移します。カタログにないソースは手元の定義 (`sources\<id>.yaml`) にします。
  元のファイルは `sources.toml.bak` に残すので、手で直していた定義はそこから戻せます。
- **dmm-games-info の取り込み**: 設定画面の「game_info.jsonl を取り込む」で、`dmm-games-info` が
  書き出した記事を取り込めます。旧形式は元の記事 ID を持たないため、同じソースで同じタイトルの
  記事を取得したときに、取り込んだ記事を引き継ぎます。旧形式の `time_range` は読み捨て、本文から
  予定を読み直します。
- **書き出し**: 設定画面で書き出し先 (例 `D:\data`) を指定すると、取得のたびに旧形式の
  `game_info.jsonl` を書き出します。`tauri-dmm-game-info` などの既存の仕組みで読めます。
  `time_range` には、読み取った予定から作った日付 (メンテナンスの時間帯が重なる日と、イベントなどの
  始まり・終わりの日) を書きます。`url_identity:` を書いたソースの本文の画像は、最後に見た配信元の
  URL に戻して書き出します (署名に期限がある配信元では、期限を過ぎると取れなくなります)。
  書き出しは同じフォルダの一時ファイル (`.game_info.jsonl.<番号>.<番号>.tmp`) に書いてから置き換えるので、
  読む側が書きかけを読むことはありません。書き出しの途中でアプリが止まって残った一時ファイルは、1 時間たってから
  次の書き出しで消します (設定などのファイルも同じ書き方で、残った一時ファイルは次に同じファイルを保存したときに
  消します)。

## 制限

- ログインやブラウザでの JavaScript の実行が必要なサイトには対応していません。
- 配信元の WAF が HTTP クライアントを拒むことがあります (ドットアビスは curl では 403 になりますが、
  このアプリの HTTP クライアントでは取得できています)。失敗が続くソースは取得間隔を最大 8 倍まで延ばします。
- カタログの定義と、手元のネットワークを許していない手元の定義の取得は、システムのプロキシを通しません
  (プロキシの先で名前解決されると、取得先を確かめられないため)。
- 本文の HTML は gpui-kit の TextView で表示します。見出し・リスト・表・画像・リンク・強調は
  出せますが、任意の CSS (文字色など) は再現しません。崩れる記事は「元の記事を開く」で読んでください。
- 署名に期限がある画像 (`url_identity:` を書いたソース) は、取得の直後に先読みしてキャッシュに入れ、
  取得のたびに最新の取得 URL を記録します。キャッシュから消えた画像を記録した URL で取れない (401・403・404・410)
  ときは、そのソースを取り直し、新しい URL で取れたら表示し直します (取れなかったあとで定期の取得が新しい URL を
  記録していれば、まずそれで取ります)。詳細ページから本文を取るソースは、その画像を持つ記事の詳細を、取得する
  期間や件数の上限によらず、一覧に載っていなくても (保存済みの URL で) 取り直します。403 は配信元の WAF のことも
  あるので、取り直しは同じ画像で 30 分あけて起動中に 3 回まで、同じソースで 1 時間に 3 回までとし、新しい URL でも
  取れなかった画像・新しい URL が見つからなかった画像 (詳細ページが消えた記事など) は、起動しているあいだは
  取り直しません。新しい URL でも取れない画像が重なったソースは 1 時間休みます。一覧や詳細を一時的に取れなかった
  ときは 30 分あけて (配信元が待ち時間を指定していればそれより後に) 取り直し、取得に失敗しているソースは、次の
  定期の取得の時刻まで待ちます。
- 画像の確かめ直しは、取得で見かけた画像 (一覧の画像と、詳細を取り直した記事の本文の画像) だけです。詳細を
  取り直さなくなった古い記事の画像は、配信元で差し替わっても前の画像を出します。1 回の取得で確かめ直すのは
  32 枚・64 MB までで、残りは次の取得に回します (失敗した画像は 30 分から 1 日まで間をあけます)。
- 一時的に取れなかった画像 (通信の失敗・5xx・429) は 30 秒後と 2 分後に読み直し、それでも取れなければ、
  記事を開き直したときに読み直します (取れても表示できなかった画像も、開き直すと読み直します)。配信元が 10 分より
  長い待ち時間を指定したときは、自動では読み直しません。
- キャッシュの画像は、書いたときの長さと SHA-256 で照らしてから表示し、合わなければ (電源が落ちて書ききれなかった
  など) 捨てて取り直します。照らすものがない前の版のキャッシュ (同じ画像を先読みと表示が同時に書いて、中身が
  混ざったものもありえます) は、表示できなかったときに起動中 1 回だけ捨てて取り直し、確かめ直しのときも ETag などを
  使わずに取り直して比べます。中身が混ざっていても表示できてしまう前の版の画像は見つけられません。旧形式から
  取り込んだ画像は取り直せないので、壊れていても消さずに残します (表示はしません)。

### 第三者のライセンスの一覧

配布物には `LICENSE` と `crates/gnn-app/assets/licenses/` をそのまま入れます (Windows は入れた場所の `licenses`、
macOS は `Game News Nexus.app/Contents/Resources/licenses`)。実行ファイルに組み込んだ Rust のクレート (間接の依存を
含む約 550 個) のライセンスの一覧 `THIRD_PARTY_LICENSES.md` は [cargo-about](https://github.com/EmbarkStudios/cargo-about)
で作ってコミットしてあり、依存か `packaging/licenses/` を変えたら作り直します (古いままだと CI が止まります)。

```bash
mise run licenses
```

`mise run licenses -- --check` は作り直さずに、古くないかだけを確かめます (CI が実行します)。作るときに次のどれかに
当たると、全部を出して止まります。

- `packaging/licenses/about.toml` の `accepted` にないライセンスのクレートが入った
- cargo-about が警告を出した (`clarify` に書いた本文のファイルの SHA-256 が、クレートを上げて変わった など)
- クレートの本文が見つからず SPDX の標準の文面に置き換わったのに、理由が `packaging/licenses/allowlist.toml` にない
- 一覧に載せるライセンスが、クレートの Cargo.toml のライセンスの式を満たさない (`clarify` が古い)
- クレートの中の NOTICE や、下の階層のライセンスのファイル (内包したコードのものなど) が一覧に入らず、理由もない

| ファイル | 中身 |
| --- | --- |
| `packaging/licenses/about.toml` | cargo-about の設定。使ってよいライセンスとその優先順・対象 (gnn-app と配る 2 つのターゲット)・本文を拾えないクレートの本文のファイル (`clarify`) |
| `packaging/licenses/allowlist.toml` | 原文を取得できず標準の文面を載せるクレートと、一覧に入れないライセンスのファイル (どちらも理由付き) |
| `packaging/licenses/about.hbs` | 一覧のひな形 (Handlebars) |
| `tools/licenses/` | cargo-about を呼んで結果を確かめ、ひな形に当てはめる (gnn-licenses) |

### CI とリリース

- CI (`.github/workflows/ci.yml`) は Windows と macOS で、書式と Clippy (`mise run lint`)・テスト・カタログの検査と、
  配布物に入れるクレートのライセンスの一覧が古くないか (`mise run licenses -- --check`) を回し、辞書がなくても `gnn-cli` を
  ビルドできることと、インストーラーと DMG の作り方 (アプリの代わりで、入れる・起動中に更新する・消すまで。起動中のアプリは
  `--quit` で終わらせ、終わらないときは閉じる) を確かめます。ワークフローとシェルスクリプトは `mise run lint-scripts`
  (actionlint・shellcheck) で検査します。
- リリースは、Actions の「Release」を `main` で実行します (`dry_run` にすると版の計算だけ)。CI が通ったコミットからだけ出し、
  版を日本時間の `yy.m.連番` (連番は月ごとに 100 から) で決めて `Cargo.toml` と `Cargo.lock` に書き、タグを付けます。
  Windows のインストーラー・macOS の DMG・`SHA256SUMS` を Release に添付し、公開した添付を照らします。

依存とツールの更新は [depup](https://github.com/owayo/depup) で行います。依存を上げたら、クレートのライセンスの一覧も
作り直します (`mise run licenses`)。mise のタスクごとに固定したツール (`lint-scripts` の actionlint・shellcheck と
`licenses` の cargo-about) は depup が上げないので、公開から 14 日以上たった版に手で上げます。

```bash
depup
```
