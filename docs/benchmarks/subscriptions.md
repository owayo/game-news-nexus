# 購読更新の I/O 計測

2026-11-13、Windows x86_64、AMD Ryzen 7 5700X、Rust 1.99.1。dev プロファイル
（自身のクレートは最適化なし、依存は `opt-level = 2`）で、一時ディレクトリの TOML を更新した。
利用者の設定やネットワークは使わない。

```powershell
mise exec -- cargo test -p gnn-core config::tests::benchmark_subscription_updates -- --ignored --exact --nocapture
```

24 件および 1,000 件の購読について、変更なし／先頭の on/off を変更する場合を測る。
各ケースは 100 回を 1 試行とし、ウォームアップ 2 試行のあとに 7 試行。処理ごとに比較する順番を交互にする。
比較用の経路も同じ排他・読み取り・複製・比較を実施し、内容が同じでも必ず保存する。起動・通信を含むアプリ全体や、
ロック導入前のコミットそのものとの比較ではない。

| 件数 | 変更 | 常に保存する経路の中央値 (ms) | 同じなら保存しない経路の中央値 (ms) | 時間の削減率 |
| ---: | --- | ---: | ---: | ---: |
| 24 | なし | 367.76 | 46.17 | 87.45% |
| 24 | あり | 359.16 | 358.74 | 0.12% |
| 1,000 | なし | 1,738.56 | 496.75 | 71.43% |
| 1,000 | あり | 1,883.89 | 1,911.11 | -1.44% |

変更なしでは、100 回の書き込み・sync・置き換えを 0 回にできる。変更ありではどちらも 100 回保存し、最終的な購読が
同じことも確かめる。単体テストには実行時間のしきい値を入れず、変更がないときにファイルの更新日時が変わらないことを検証する。

I/O のばらつきは大きい。1,000 件・変更ありの範囲は、比較用が 1,873.30〜2,290.97 ms、更新後が
1,863.07〜2,322.57 ms で、中央値では 1.44% 遅い。両方とも同じ保存処理を通るが、この計測だけで退行がないとは断定しない。
変更なしのケースでは全試行で改善したため、不要な再保存を省く処理を採用する。メモリの比較は未実施。
購読の最新値を読む処理と初期化の排他は、設定の消失を防ぐために必要な処理として維持する。
