# 使い方の詳細

## キーボード

macOS では `Ctrl` の代わりに `⌘` を使います (`⌘R`・`⌘F`・`⌘1`・`⌘2`・`⌘,`・`⌘W`・`⌘Q`)。

| キー | 操作 |
| --- | --- |
| `Ctrl+R` / `F5` | すべて取得 (ニュース画面では表示中のソース) |
| `Ctrl+F` | 検索欄へ |
| `J` / `↓`、`K` / `↑` | 次・前の記事 (一覧にフォーカスがあるとき) |
| `O` / `Enter` | 元の記事をブラウザで開く |
| `M` | 既読・未読を切り替える |
| `Shift+A` | 表示中の記事をすべて既読にする |
| `Ctrl+1` / `Ctrl+2` / `Ctrl+,` | ニュース / ソース / 設定 |
| `Ctrl+W` | ウィンドウを閉じる (閉じるボタンと同じ。設定によりトレイ・メニューバーに残り、残さない設定なら終了する) |
| `Ctrl+Q` | 終了 |

macOS では、ほかに `⌘H` (隠す)・`⌥⌘H` (ほかを隠す)・`⌘M` (しまう) が使え、メニューバーのアプリのメニュー (設定・編集・表示・ウインドウ) からも同じ操作ができます。

## macOS で使うとき

メニューバーのアイコンを押すとメニュー (開く・今すぐ取得・終了) が出ます (Windows のトレイと違い、左クリックでもメニューです)。

Dock にアイコンが出るのはウィンドウを開いている間だけです。ウィンドウを閉じると、メニューバーのアイコンだけで常駐して取得を続けます。

「ログインしたら自動で起動する」は `~/Library/LaunchAgents/io.github.owayo.game-news-nexus.plist` を書き、次のログインから効きます。アプリを別の場所へ移したら入れ直してください。ダウンロードしたアプリを 「アプリケーション」フォルダへ移さずに開いているときは登録できません。システム設定の「ログイン項目」で止めた場合、アプリの設定画面のスイッチには表れません。

通知は `Game News Nexus.app` から起動したときだけ出ます (`cargo run` などで直接起動したときは出ません)。初めて通知するときに、通知を許可するかを聞かれます。

## 予定の読み取り

お知らせの題名と本文から、メンテナンスの予定 (開始・終了) と結果 (完了・中止・延期・延長) と、イベント・ガチャ・ キャンペーン・販売・受け取りの期間を読み取ります。

期間の開始のバッジは青、終了は橙です。メンテナンス中は赤、終了の報告は緑で表示します。

日本語の文は、形態素解析器 [hasami](https://github.com/owayo/hasami) と、実行ファイルに埋め込んだ辞書 (IPAdic) で読みます。「予定していたメンテナンスを中止します」のような修飾節や、「終了していません」「終了したら」 「中止する場合があります」のような否定・条件・可能性を読み分けます。

本文の見出し・リスト・表・取り消し線・「項目名：値」の行・追記の区画も手がかりにします。補填の受け取り期限や販売の終わりは、メンテナンスの時間として扱いません。

別の記事で報告された完了・中止・延長は、予告の記事のメンテナンスにも反映します (対象と時間帯で 1 つに決まるときだけ結び付け、日付が近いだけでは結び付けません)。
- 「Android版・iOS版」のように 1 つの時間帯に複数の対象が書かれていれば、対象ごとに読み、「iOS版のみ完了」のような一部の対象だけの報告もその対象に当てます。画面では、同じ状態のものを 1 つのバッジにまとめます。
- 「現在メンテナンスを実施しております」のように、開始の時刻がなく実施中とだけ書かれた告知も、いつの時点で実施中だったか (追記の日時、なければ投稿日時) と一緒に読み、「メンテ中」と出します (終わりが書かれていなければその時点から 24 時間まで)。
- 延長は延長する前の終わりと新しい終わりを、日程変更は変更ごとの前と後を読み、「延長 11/12(木) 17:00 → 19:00」 「日程変更 11/10(火) 14:00–17:00 → 11/12(木) 14:00–17:00」のように並べて出します。イベントなどの期間の延長・ 変更も読み、延びた期間のバッジには「(延長)」を付けます。今日・明日かは、変更の後の期間で決めます。始まる前に書かれた「延長します」は実施中とは扱わず、延長する前の終わりが書かれていなければ、それまでの予定の終わりを推定で出します。
- 決められない日時 (曜日の食い違い、終わりが始まりより前、「サーバー時間」の地域時刻が分からないなど) は推測せず、記事の詳細に理由を出します。年の書かれていない日付は投稿日に近い年にし、`24:59` は翌日の 0:59 と読みます。
- 予定の時間内でも、完了の報告がなければ予定のままとし、終了予定を過ぎても完了とはみなしません (「終了予定を過ぎています」と出します)。日付だけの予定は「メンテ中」にせず、所要時間から求めた終わりには 「頃」を付けます。
- 読み取った結果は、記事から作り直せるデータとして保存します。読み取り方を変えた版のアプリでは、起動したときに保存済みの記事を読み直します。

## 制限

- ログインやブラウザでの JavaScript の実行が必要なサイトには対応していません。
- 配信元の WAF が HTTP クライアントを拒むことがあります (ドットアビスは curl では 403 になりますが、このアプリの HTTP クライアントでは取得できています)。失敗が続くソースは取得間隔を最大 8 倍まで延ばします。
- カタログの定義と、手元のネットワークを許していない手元の定義の取得は、システムのプロキシを通しません (プロキシの先で名前解決されると、取得先を確かめられないため)。
- 本文の HTML は gpui-kit の TextView で表示します。見出し・リスト・表・画像・リンク・強調は出せますが、任意の CSS (文字色など) は再現しません。崩れる記事は「元の記事を開く」で読んでください。
- 署名に期限がある画像 (`url_identity:` を書いたソース) は、取得の直後に先読みしてキャッシュに入れ、取得のたびに最新の取得 URL を記録します。キャッシュから消えた画像を記録した URL で取れない (401・403・404・410) ときは、そのソースを取り直し、新しい URL で取れたら表示し直します (取れなかったあとで定期の取得が新しい URL を記録していれば、まずそれで取ります)。詳細ページから本文を取るソースは、その画像を持つ記事の詳細を、取得する期間や件数の上限によらず、一覧に載っていなくても (保存済みの URL で) 取り直します。403 は配信元の WAF のこともあるので、取り直しは同じ画像で 30 分あけて起動中に 3 回まで、同じソースで 1 時間に 3 回までとし、新しい URL でも取れなかった画像・新しい URL が見つからなかった画像 (詳細ページが消えた記事など) は、起動しているあいだは取り直しません。新しい URL でも取れない画像が重なったソースは 1 時間休みます。一覧や詳細を一時的に取れなかったときは 30 分あけて (配信元が待ち時間を指定していればそれより後に) 取り直し、取得に失敗しているソースは、次の定期の取得の時刻まで待ちます。
- 画像の確かめ直しは、取得で見かけた画像 (一覧の画像と、詳細を取り直した記事の本文の画像) だけです。詳細を取り直さなくなった古い記事の画像は、配信元で差し替わっても前の画像を出します。1 回の取得で確かめ直すのは 32 枚・64 MB までで、残りは次の取得に回します (失敗した画像は 30 分から 1 日まで間をあけます)。
- 一時的に取れなかった画像 (通信の失敗・5xx・429) は 30 秒後と 2 分後に読み直し、それでも取れなければ、記事を開き直したときに読み直します (取れても表示できなかった画像も、開き直すと読み直します)。配信元が 10 分より長い待ち時間を指定したときは、自動では読み直しません。
- キャッシュの画像は、書いたときの長さと SHA-256 で照らしてから表示し、合わなければ捨てて取り直します。検証情報がない画像は、表示できなかったときに起動中 1 回だけ取り直します。配信元の URL が記録されていない画像は取り直せません。
